# 数据探查报告

本报告由 `scripts/profile_data.py` 从 `data/bank_risk.sqlite` 计算生成，所有数字都来自查询，数仓重建后可以重新生成。每节后面的解读说明这些数据对系统设计的影响。

交易流水占了绝大部分数据量，时间覆盖 1993-01-01 至 1998-12-31。客户表的日期是出生日期，账户表的日期是开户日期，都不是业务发生的时间。系统把"上个月"这类相对时间换算到交易与事件的时间轴上，参考日期取交易的最后一天 1998-12-31。

### 按放款年份的不良率

| 放款年份 | 放款笔数 | 不良笔数 | 不良率 |
|---|---|---|---|
| 1993 | 20 | 4 | 20.00% |
| 1994 | 101 | 14 | 13.86% |
| 1995 | 90 | 12 | 13.33% |
| 1996 | 117 | 16 | 13.68% |
| 1997 | 196 | 26 | 13.27% |
| 1998 | 158 | 4 | 2.53% |

不良率按放款年份归属。1998 年放款的不良率只有 2.53%，而 1994 至 1997 年在 13.27% 至 13.86% 之间（1993 年放款很少，不作比较）。这不是风险变低，而是这些贷款发放时间短，违约还没来得及发生。按放款日期统计的不良率天然有这种账龄效应，比较不同年份时需要注意。

### 账户、卡、权限关系

| 维度 | 取值 | 数量 |

每个账户恰好有一个所有人（OWNER），其余为授权使用人（DISPONENT）。按账户统计客户属性时必须限定 OWNER，否则有授权使用人的账户会被重复计数；语义层通过一个限定了 OWNER 的别名来关联客户表。

## 数据质量问题

| 问题 | 影响行数 | 处理 |
|---|---|---|
| trans.type 存在未文档化编码 VYBER | 16,666 | 出账口径须包含 VYDAJ 与 VYBER |
| trans.operation 为 NULL | 183,114 | 全部为利息入账（k_symbol = 'UROK'） |
| trans.k_symbol 为 NULL | 481,881 | 归为未标注 |
| trans.k_symbol 为单个空格 | 53,433 | 归为未标注 |
| order.k_symbol 为空串 | 1,379 | 归为未标注 |
| trans.balance 为负（透支） | 2,999 | 余额可为负 |
| district.A4 至 A7 为文本型数字 | 77 | 数值比较前需 CAST |
| district.A12 / A15 空值 | 1 | Jesenik 区县 |
| 金额单位描述冲突 | 全部金额字段 | 原始文档为捷克克朗，BIRD 标注为 USD |

除金额单位外，这些处理都写进了语义层的字段说明和取值定义，第三层生成 SQL 时看到的表结构说明也包含它们；金额单位按原始文档取捷克克朗，说明在 `semantic/catalog.yaml` 的开头。
