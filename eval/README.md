# 评估集

## 构成

系统用两套题评估。自建评估集 `domain_eval.yaml` 共 101 题，按期望的处理路径分层编写：第一层（月度指标表）16 题，第二层（语义层编译）35 题，第三层（生成式 SQL）30 题，应当澄清的问题 10 题，与数据无关的问题 5 题，口径问答 5 题。每道取数题都有人工编写并执行校验过的金标 SQL；第一、二层的 51 题另有标注好的查询意图（IR），其中 7 题还标注了语义等价的备选写法，用来计算槽位准确率。外部基准是 BIRD financial 的 2025-11-06 清洗版，共 106 题（简单 24、中等 25、困难 57），由 `scripts/download_data.py` 下载，只用于评估第三层。

评估集在开发系统之前写好并冻结。划分规则是固定的：在每个类别内按序号 i（从 1 开始），i 除以 5 余 1 或 3 的题划入开发集，其余划入测试集，结果是开发集 41 题、测试集 60 题。开发集用于调试，测试集只用于最终报告。

为了在更大的表结构上评估第三层，`scripts/build_distractors.py` 还可以构建一个大表结构环境：把 BIRD dev 其余 10 个库的 67 张表作为干扰表混入，financial 因此共有 75 张表，自建库共有 77 张业务表。题目与金标都不变，只是检索和生成时可选的表变多了；干扰表每张最多保留 1,000 行，字段说明由 BIRD 自带的说明自动生成。评估脚本加 `--distractors` 即在这个环境中运行，见实验 X6。

另有一份规则探测集 `rule_probes.yaml`（44 题），不属于评估集，专门用来检验规则层在口径问答和域外判断上的精确率；`x2_format_only.yaml` 列出实验 X2 中只有输出形式与金标不同的题目及理由。

## 约定

题目中的相对时间、缺省值和输出形式按以下约定标注金标：

| 类别 | 约定 |
|---|---|
| 参考日期 | 1998-12-31，即数据的最后一天 |
| 相对时间 | 今年为 1998 年；上个月为 1998 年 11 月；上季度为 1998 年第三季度；近 N 个月包含当月；今年以来为 1998-01-01 至 1998-12-31 |
| 未指定时间 | 不限时间，统计全部历史数据，并在答案中注明 |
| 周期 | 自然年、自然季度、自然月；上半年为 1 至 6 月 |
| 对比 | 同比为上一年同期；环比为紧邻的上一个同长度周期 |
| 业务口径 | 以 `semantic/metrics.yaml` 为准，例如不良为状态 B 或 D，不良率按放款日期归属，出账包含 VYDAJ 与 VYBER |
| 输出 | 分组只列出有数据的组；比率以小数表示；趋势的周期写作 YYYY-MM、YYYY-Qn 或 YYYY |

## 判定规则

| 指标 | 规则 |
|---|---|
| 执行准确率（BIRD 官方） | 预测结果集与金标结果集作为集合严格相等 |
| 执行准确率（自建集） | 金标的每一列都能对应到预测结果中不同的一列，且逐行一致；允许预测多出说明列；数值允许 1 至 4 位小数的舍入差异；只有要求排序的题比较行序 |
| 槽位准确率 | 预测的 IR 与金标 IR（或任一语义等价的备选写法）逐槽位比较 |
| 路由准确率 | 预测的处理路径与标注一致 |

## 金标校验

金标先后经过四道检查。`scripts/check_eval_set.py` 执行全部金标 SQL，检查结果非空、耗时正常，并确认取前 N 名的题在边界上没有并列；101 道自建题与 106 道 BIRD 题全部可以执行。`scripts/crosscheck_eval.py` 用两条独立的计算路径核对同一个数量，例如分组之和必须等于总数，20 项全部一致。`review_checklist.md` 是抽样 20 题的人工口径审阅记录，逐项列出指标、时间范围、筛选条件和输出形式，核对结果为全部符合。最后，`tests/test_eval_harness.py` 把金标本身当作预测送进评估程序，要求每一项指标都是 100%，以此确认评估代码没有问题。
